# Трезвый водитель 44 — EYEWITNESS

Приложение очевидца: активное согласие, анонимные сообщения о происшествии, фото/видео, координаты, уведомление о получении и отзыв согласия.

## Сборка и проверки

Нужны Android SDK 37, Build Tools 36.0.0 и полный JDK (в проверке использован JDK 25). Укажите SDK в локальном local.properties, не включайте его в поставку. Используйте Gradle wrapper из этого репозитория.

```powershell
.\gradlew.bat assembleDebug testDebugUnitTest lintDebug -PapiBaseUrl=https://xn--e1afhclgq.xn--p1ai:4443/
```

Адрес API задаётся при сборке; допускается только HTTPS с завершающим `/`. Выпущенные тестовые APK имеют отдельный applicationId с `.test`, тестовую подпись и метку «тест». Их нельзя использовать для реальных персональных данных или считать опубликованным рабочим релизом. Тестовый API на VDS требует отдельного развёртывания; его фактический статус указан в TEST_RESULTS.md в общей папке проекта.

Firebase/Google Messaging, внешние карты/CDN и облачная геолокация удалены. Уведомления используют собственный сервер; Android вправе задержать фоновую задачу, поэтому приложение не обеспечивает само по себе круглосуточное дежурство и норматив реакции 15 минут.

Сессия хранится через Keystore, резервное копирование отключено. Общая запись сообщения сохраняется после первого подтверждения сотрудником и удаляется по сроку до 30 суток либо по отзыву согласия очевидцем.

Лицензии и состав зависимостей находятся в `third_party/` и доступны в интерфейсе. Полный перечень правок и ограничений: REQUIREMENTS.md, FIXES.md, LICENSES.md, TEST_RESULTS.md рядом с тремя репозиториями.

## Конфигурация сборки

Адрес API хранится в `config/app.properties`. Для будущего боевого домена скопируйте `config/production.example.properties` в `config/local.properties` и замените значения. Параметры Gradle -P имеют приоритет. EYEWITNESS также использует privacyPolicyUrl, privacyConsentUrl, privacyRegulationUrl и consentVersion. Ссылки открываются в браузере; смена политики/согласия запрашивает согласие повторно. После изменения конфигурации нужно пересобрать APK.

## CI/CD: обычные GitHub Releases

Push main и pull request запускают unit tests, Android Lint, сборку и список зависимостей. Проверки и артефакты сохраняются на 14 дней. Публикация после успеха main создаёт обычный GitHub Release, без pre-release. В релиз входят APK, SHA256SUMS.txt, BUILD-INFO.json с фактически встроенной конфигурацией и THIRD-PARTY-NOTICES.zip.

По умолчанию остаётся debug APK с .test и прежним тестовым ключом — текущий сервер только тестовый. Для настоящего Android release выберите build_variant=release при ручном запуске либо настройте Variable APK_BUILD_VARIANT=release. Нужны боевые URL в Variables и отдельные APK_RELEASE_* Secrets; при отсутствии рабочего ключа fallback на debug-ключ не выполняется. Обычный GitHub Release сам по себе не превращает тестовый APK в рабочий.

Ручной запуск: Actions → Android APK → Run workflow → main. publish=false оставляет только сборку и проверки. Pull request не публикует APK и не получает ключ. APK_TEST_KEYSTORE_BASE64 сохраняет прежнюю подпись тестовых версий. Внешние Actions закреплены SHA; подпись выполняется отдельным заданием без запуска Gradle с ключом.

Полная инструкция сервера, домена, документов и боевой подписи: [docs/PRODUCTION.md](docs/PRODUCTION.md). Там описаны все Variables/Secrets и конфигурация nginx/systemd из серверного репозитория.

## Последовательные версии

Автопубликация main включена. Новые теги — v1.0.0, v1.0.1, v1.0.2 и далее; номер CI больше не используется как версия. Следующий patch определяется по опубликованным vX.Y.Z, а Android versionCode — на единицу больше опубликованного значения с учётом прежних test-N. Ошибка CI и publish=false не расходуют версию. Весь workflow main сериализован, чтобы параллельные сборки не выбрали одинаковый номер. Debug сохраняет суффикс -test в versionName и отдельный applicationId. Старые теги test-N остаются в истории.

## Production на силенок.рф

Автоматически публикуется только Android release с постоянным рабочим ключом: без .test, без тестового суффикса версии и без тестовых меток интерфейса. API: https://силенок.рф/ на стандартном HTTPS-порту, ссылки на политику/согласие/регламент — /legal/policy, /legal/consent, /legal/regulation этого же домена. Конфигурация остаётся в config/app.properties и GitHub Variables. Диагностический debug можно собрать вручную, но он не публикуется в Releases.

Production APK имеет другой applicationId и ключ, чем прежняя .test-сборка: установите рабочий APK как отдельное приложение. Постоянный ключ не менять при последующих обновлениях. Закрытые резервные копии ключей и паролей находятся у root VDS в /var/lib/gibdd-signing, значения не включены в репозиторий. Сертификаты публичны; подпись каждого релиза проверяется CI.
